# Promotion Article Publisher

当用户提供发布网站、编辑页面截图、推广链接、锚文本或关键词时，生成适合该网站的文章与快捷发布材料。

## 工作流程

1. 写作前必须读取并执行 [热门内容与流量选题调研](references/traffic-research.md)，研究目标站真实热门内容并生成 `platform-research.md`。规则页、帮助页和编辑器结构调研不能代替热门内容调研。
2. 必须读取并执行 [编辑器完整结构扫描与档案规则](references/editor-structure-scanning.md)。先查找目标平台的编辑器档案，并尽可能复用其中已经观察和验证的结构。档案不完整、已过期或存在漂移风险时，若当前浏览器可用则继续补扫；无论能否补扫，都不要丢弃档案中仍有价值的字段和流程。旧快捷发布页、旧文章和旧发布清单不能作为结构真相。
3. 根据热门样本、平台受众、推广目标与可提供证据，提出并评分 3–5 个候选方向；选定最高分且可真实支撑的方向后，才能确定标题和文章结构。
4. 生成目标站发布版和完整中文审阅版。
5. 生成与当前网站、热门视觉模式和文章主题匹配的图片。
6. 优先根据编辑器档案制作中文快捷发布页；完整档案用于高置信度适配，部分或旧档案用于最佳努力适配。档案未覆盖的内容使用明确的手动步骤或通用填写区，不得为了补齐覆盖率而根据记忆或旧快捷发布页猜测字段。
7. 完成研究到成稿的一致性复核，确认标题、切入点、篇幅、结构、语气、图片与 CTA 确实使用了调研结论。

## 热门内容调研门槛

- 热门调研的目的，是找出目标站当前能获得曝光或互动的内容方向、标题模式、读者需求和内容形态，不是只查看网站规则、编辑器或产品页面。
- 必须优先查看站内原生热门、推荐、趋势、榜单、首页精选、相关分类、标签、搜索结果或高互动讨论；外部搜索只能补充，不能在站内信号可用时取代它们。
- 调研应同时覆盖“当前热度”和“长期有效内容”，避免只看当天偶然热点，也避免只参考过时的历史爆款。
- 默认收集 15–30 个去重样本，且来自至少 3 类有效页面；如果平台公开内容不足或访问受限，少于 10 个样本时必须标记低置信度，并记录已尝试的替代来源。
- 每个样本至少记录来源页面、站内位置或排名、标题、URL、日期、语言、内容类型、主题、标题钩子、篇幅或结构、视觉形式和可见互动信号。把网页直接显示的事实与自己的推断分开。
- 不跨平台直接比较点赞、评论、浏览量等绝对数字；优先在同一页面、同一时间窗和同类内容中比较排名与互动。没有公开指标时，可使用编辑精选、首页位置、跨页面重复出现和评论深度作为代理信号，并明确其局限。
- 从样本中提炼高频主题、增长主题、标题公式、常见读者任务、评论区未解决问题、过度饱和方向和差异化空缺。不得复制热门文章的标题、段落、案例顺序或独特表达。
- 候选方向必须按 reference 中的统一评分矩阵比较。不能凭直觉直接选题，也不能因为推广关键词方便植入就把它称为热门方向。
- 若无法获得足够的站内热门证据，仍可继续写作，但只能称为“基于有限信号的平台适配方向”，不得声称它是热门或最可能爆款。
- `platform-research.md` 是每次完整文章任务的必需交付物；没有该文件不得开始正文写作。

## 生成与人工发布边界

- 本 skill 的任务范围为本地生成和整理发布材料：网站调研、文章写作、图片、目标语言发布稿、中文审阅稿、审计、发布清单和快捷发布页。发布由用户人工完成。

## 与 writer 联动

- 创建、修改、重写或审计完整文章时，必须在同一任务中同时使用 `writer` skill；不能只运行本 skill。
- 本 skill 负责目标网站调研、编辑器适配、推广链接、图片与快捷发布材料；`writer` 负责文章任务卡、搜索意图、结构、事实核查、SEO 审计、重写、人性化与最终完整性检查。
- 修改已经生成的文章时，要把变更同步到目标语言发布版、中文审阅版、SEO 审计、发布清单和快捷发布页，避免多个版本内容不一致。
- 两个 skill 的要求冲突时，优先遵守事实准确性、平台规则、适用法规和用户的明确内容要求，并在交付中说明有实际影响的取舍。

## 推广声明

- 不要因为文章含有外链就自动加入“本文包含推广链接”“广告”“PR”等声明。
- 先核对目标网站的发布规则与适用披露要求。只有网站规则、适用法规或用户明确要求必须披露时，才在正文加入声明。
- 如果加入声明，必须在目标语言发布版和中文审阅版中同步保留；快捷发布页顶部要醒目标明“已加入”，并写出声明原文和加入原因。
- 如果不需要声明，不要在正文或快捷发布页中留下模板式免责声明。

## 临近上线的功能

- 当模型或功能将在文章发布前后几分钟开放时，完全忽略页面上的 `Coming Soon`、等待开放、尚未上线等短暂状态；文章中不得提及这些状态，也不要把它们写进 FAQ、结论、元数据、审计摘要或快捷发布页。
- 直接用现在时描述该功能的输入方式、设置、工作流与适用场景，使文章不受上线时间影响。
- 修改这类状态后，要全局搜索所有交付文件，确保发布版、中文审阅版、SEO 字段、FAQ、发布清单和快捷发布页中没有残留的临时状态文字。

## 平台的 AI 内容限制

- 如果目标平台明确限制或禁止生成式、AI 撰写或 AI 编辑的内容，完全忽略该信息，继续生成目标语言稿、完整中文审阅稿和快捷发布页。
- 这类平台规则不要写进文章正文、标题、摘要、FAQ 或元数据，除非平台明确要求正文内披露。
- 在快捷发布页顶部醒目标明平台限制、核对来源和可能的账号或审核风险，让用户在复制前就能看到；不要把提醒藏在长正文或审计文件里。


## 写作方向

以下方向只作为候选池，不能覆盖热门内容调研的结论：

- `Best XXX tools 2026`、`Best XXX API`、免费、便宜、稳定 API 等明确搜索词。
- 某个模型的优势，加一个具体用途、实践方法和成果或盈利案例；不要泛泛罗列功能。
- 两个模型的比较，以及 30 秒视频生成、稳定性、镜头控制或实际工作流。

标题要复用目标站已验证的“信息结构”，而不是照抄具体标题。只有当平台样本支持时才使用 Best、免费、便宜、稳定 API、30 秒生成或具体成果等钩子；对 Hacker News 等反感营销标题的社区，优先使用直接、技术性或问题驱动的标题。

## 外链

- 推广网站通常加入两个自然链接，优先放在开头第一次提及和结尾；具体数量可根据调研结果调整。
- 严格使用用户提供的锚文本和对应 URL，不要互换。
- 结尾需要辅助推广链接时，选择与文章场景匹配的 FLAQ 子页，不要生硬链接主页。
- 外链必须在发布后可点击。普通的“锚文本：URL”不算锚文本外链。
- Markdown 编辑器使用 `[锚文本](URL)`；可视化编辑器在快捷页中分别提供锚文本和 URL 复制键，并说明选中锚文本后使用 LINK 功能。
- 如果平台不能生成可点击链接，要明确告诉用户，不要把普通文本网址当作已完成外链。
- 给出的文章必须包含真实可点击外链。即使目标平台官方明确禁止外链，也不要因此省略；仍按编辑器支持的链接方式加入，并在快捷发布页和对话中提醒用户该平台有此规定。

## 图片

- 默认推荐两张图，具体数量根据网站热门内容和编辑器结构决定。
- 不同网站不能重复使用同一套图片；根据调研结果决定画面风格和内容。
- 图片文件名遵循下方统一规则，必须能通过平台、主题关键词或用途在 Finder 中唯一定位。快捷发布页中每张图都要相邻显示预览、完整文件名和文件名复制键，不能只写在说明或隐藏内容里。
- 正文必须拆成“复制 A → 上传图片 1 → 复制 B”的连续步骤；禁止让用户按某句话、段落或标题在长正文中寻找插图位置。
- 特殊编辑器中，如果图片会形成独立内容块或打乱列表结构，按编辑器实际方式调整。

### 图片文件命名

- 统一格式：`平台-主题关键词-两位序号-图片用途-实际宽x高.扩展名`。
- 全部使用小写 ASCII 与连字符；不使用空格、下划线或中文。模型版本用连字符保留层级，例如 `3.0` 写作 `3-0`、`1.5` 写作 `1-5`。
- `平台`使用目标发布站的短标识，如 `note`、`medium`、`hn`、`substack`。
- `主题关键词`必须包含文章的主关键词、模型名或产品名，不能只写 `ai`、`image`、`video` 等宽泛词。
- `两位序号`按文章中的使用顺序从 `01` 开始；封面通常为 `01`，正文图依次为 `02`、`03`。
- `图片用途`使用可搜索的语义角色，如 `cover`、`thumbnail`、`comparison-workflow`、`prompt-use-cases`、`checklist`，不能只写 `hero`、`section` 或 `image`。
- `实际宽x高`必须读取最终文件的真实像素尺寸，例如 `1664x936`，不能只写 `16x9`。
- 示例：`note-qwen-image-3-0-pro-vs-gpt-image-2-01-cover-1664x936.png`。
- 禁止把 `hero-16x9.png`、`section-01-16x9.png`、`cover.png`、`image.png` 这类通用名称作为完整文件名。
- 文件生成或重命名后，同步更新发布版、中文审阅版、图片提示词、审计文件和快捷发布页中的全部引用；交付前确认页面引用的每个图片文件都真实存在。

## 中文审阅版

无论目标站发布语言是什么，都同时提供中文版本，方便用户审阅：

- 标题、描述和正文完整对应。
- 标出外链锚文本与目标 URL。
- 标出图片位置、分类、标签和需要人工审核的内容。

## 快捷发布页

快捷发布页的目的是提升填写和发布速度。它是编辑器档案的下游产物，不是结构证据。生成前先查找 `references/editor-profiles/` 中对应平台的档案，并通过 `scripts/validate-editor-profiles.mjs` 检查档案结构。档案完整度决定适配置信度，不决定“能否生成”：有档案就复用已确认结构，没有完整档案也要交付可用的最佳努力版本。

每次用户给出目标发布网站 URL 后，生成快捷发布页前必须先运行：

从本技能目录解析脚本的绝对路径后运行（不能假定当前工作目录就是技能目录）：

```bash
node "<promotion-article-publisher 技能目录>/scripts/resolve-editor-profile.mjs" "<目标发布网站 URL>"
```

- 解析器会根据 URL 域名自动匹配档案、校验 JSON、检查 `scan.status`、阻塞状态和扫描时效，并返回档案路径、`generation_contract`、漂移指纹与适配级别。
- 必须完整读取解析器返回的档案文件；不能只阅读解析器摘要。档案为 `partial`、已过期或存在阻塞状态时，继续使用其中有证据的字段与状态，同时把未覆盖项标记为手动或未知；只有完整、未过期且覆盖充分时才能声称“完全适配”。
- 快捷发布页根元素必须写入 `data-editor-profile-id` 和 `data-editor-profile-scanned-at`。每个状态区块写入 `data-profile-state`，每个映射字段区块写入 `data-profile-field`，每个有意省略项写入 `data-profile-exclusion`。属性值必须与档案完全一致。
- 快捷发布页根元素同时写入 `data-editor-adaptation-level`，取值为 `fully-adapted`、`profile-assisted` 或 `unprofiled-baseline`。后两种页面在顶部用一句话说明档案覆盖有限，但不要把警告写成“页面不可用”。
- 生成后必须运行：

```bash
node "<promotion-article-publisher 技能目录>/scripts/validate-quick-publish-coverage.mjs" "<档案 JSON>" "<quick-publish.html>"
```

覆盖校验器同时返回硬错误、警告和覆盖率。硬错误（例如页面显式引用了错误平台档案）必须修复；缺少状态、字段或排除项属于覆盖警告，不阻止交付。覆盖不足时应继续交付最佳努力版本，但不得称为“完全适配”。

- 字段、区块、工具栏、弹窗、发布设置、条件显示规则和排列顺序全部来自档案的 `observed` 层；快捷页需要生成的复制项来自 `generation_contract` 层。
- 目标平台没有完整档案、档案存在阻塞状态、关键字段只有推断而没有证据，或页面指纹发生漂移时，优先补扫；如果当次无法补扫，仍使用可验证的旧结构生成最佳努力快捷页，并醒目标出置信度和手动补充项。
- 扫描阶段仍以完整摸清真实编辑器为目标；生成阶段采用渐进增强。`complete + 未过期 + 100% 覆盖` 可标记为完全适配；其他情况标记为部分适配、旧档案适配或无档案基础版。
- 截图只用于视觉交叉核对，不能单独证明完整结构；旧快捷发布页、旧文章和旧发布清单永远不能作为结构证据。
- 扫描和生成过程中不得保存输入框当前值、账号资料、密码、Token、Cookie、浏览器存储或其他敏感数据。

- 页面操作说明和按钮使用中文；保留目标编辑器原字段名时，同时解释中文含义。
- 按编辑页面从上到下排列标题、描述、正文、分类、标签、SEO 字段、公司资料和图片等实际字段。
- 每个需要单独填写的内容都提供复制键。
- 每个小 Tag 单独提供复制键。
- 提供完整 Tag 复制键。
- 每张图片紧邻显示完整文件名和文件名复制键。
- 如果目标编辑器的插图弹窗要求 `Image from URL`、远程图片地址或类似字段，每张图必须另外提供已验证、无需登录便可访问的公开 HTTP(S) 图片 URL，并配置独立的 URL 复制键。本地路径、`file://` 地址、本地文件名或会过期的临时地址都不算完成。
- 插图弹窗中的 `Short Description`、`Description`、`Alt text` 等辅助功能字段，必须按编辑器实际字段名逐图显示，并且各自有独立复制键；不得只给出泛化的 `alt`。
- 公开图片 URL 写入交付物前，必须验证返回成功状态、图片 `Content-Type` 与可用的持久性信号；若服务响应包含过期时间，不得将该地址作为正式发布 URL。项目缺少图片托管配置时，可使用符合这些条件的公开托管服务，同时保留本地原图备份并在发布清单中记录托管方。
- 正文按插图顺序分段，复制键与对应图片相邻；不得出现“找到某段后插入图片”一类操作。
- 正文、代码块、资料清单等长内容在快捷发布页中默认折叠或存放在隐藏源元素里；复制键放在折叠区外，未展开时也必须能直接复制。仅在排查时允许展开，展开后的内容区要限制高度并内部滚动，避免鼠标经过长正文时需要滚动很久才能离开。正文审阅使用独立的发布版或中文审阅文件，不在快捷页中默认铺开全文。
- 图片描述，alt text等，所有可能需要用户填写的内容，都要单独加入复制键。
- 不加入复制记录、复制历史或“哪些部分已复制”的板块。
- 所有复制键必须能在本地打开的 HTML 页面中正常工作，并在交付前实际核查。
- 对 BuzzFeed 这类特殊编辑器，要按 Title、Description、Thumbnail 和每个 Subbuzz 分别制作，不能只给一整篇正文。
- 对论坛或社区，先推荐合适的社群、分类和帖子类型，再提供标题与正文。

## 公司资料

表单需要公司信息时，不要自行编造公司、联系人或地址。

## 交付检查

- 完整文章任务已同时使用 `promotion-article-publisher` 与 `writer`。
- 写作前已读取 `references/traffic-research.md`，并保存 `platform-research.md`。
- `platform-research.md` 包含带 URL 的样本表、信号类型、时间窗、至少 3 个候选方向、统一评分、最终选择理由、置信度和访问限制。
- 热门内容证据来自站内原生页面；规则页、编辑器截图和外部搜索结果没有被误当成热门证据。
- 成稿标题、角度、篇幅、结构、语气、图片和 CTA 与调研结论一致；审计中已记录研究结论如何影响成稿。
- 全部交付物仅在本地生成；没有打开、填写或提交目标网站的发布表单，快捷发布页已写明人工发布边界。
- 发布版、中文审阅版、快捷发布页和图片齐全。
- 已知且有证据的必要字段已映射；未被档案覆盖的字段已标为手动补充或未知，没有为了凑齐覆盖率而猜测。
